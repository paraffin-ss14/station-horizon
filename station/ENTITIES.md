# Сущности и контент из данных

Первый движковый слой подключён к существующей станции: реестр сущностей,
идентификаторы с поколением, данные компонентов, прототипы и шаблон карты.
Роли, физика, инвентарь, доступы и сетевые раунды продолжают работать.

## Загрузка без пересборки

Из корня репозитория:

```powershell
cargo run --manifest-path station/Cargo.toml -p station-server --locked -- --listen 127.0.0.1:7777 --content station/content/station.json
cargo run --manifest-path station/Cargo.toml -p station-client --locked -- --connect 127.0.0.1:7777
```

Локальный режим:

```powershell
cargo run --manifest-path station/Cargo.toml -p station-client --locked -- --content station/content/station.json
```

Без --content используется встроенная копия стандартного JSON. При --connect контент
выбирает сервер, клиент получает параметры и сущности по сети. Файл загружается один
раз при запуске и сохраняется неизменяемым набором данных для всех следующих раундов.
Изменения файла применяются после перезапуска сервера. Сохранение текущего раунда
и горячая перезагрузка не добавлены.

## Что вынесено в station/content/station.json

- Прототипы предметов: название/описание (ключ перевода либо обычный текст), встроенный
  тип поведения, размер, масса, допустимые слоты, размер предмета, вместимость,
  цвет, куб или billboard с существующим спрайтом.
- Стандартная геометрия: заполненные параллелепипеды base и departments.
- Размещение предметов по именованным ключам, двери с доступами и названиями.
- Точки появления, стартовые комплекты профессий.
- Радиус тела, скорость и размер спрайта персонажа. Параметры используются серверной
  физикой, клиентским предсказанием и рендерером.

Новый обычный предмет добавляется прототипом kind="Generic" и записью map.items;
новый предмет не требует Rust-кода. Новое поведение, например электропитание, требует
системы на Rust. Процедурный астероид Horizon пока включается флагом map.asteroid,
его генератор сохранён в коде.

Проверки до создания мира: версия, неизвестные поля, существование прототипов,
дубликаты ключей размещения/слотов комплекта, совместимость предмета со слотом,
диапазоны физических параметров и цветов, точки появления, бюджет вокселей.
Лимиты: файл 1 МиБ, 256 прототипов, 512 начальных предметов, 64 двери, 200000
вокселей в описании заполнений. Неверный файл завершает запуск с сообщением ошибки.

## Сущности и жизненный цикл

`sim/src/entity.rs`: EntityId { world, slot, generation }. Удалённый слот реестра
можно использовать снова, но поколение увеличивается. Новый Simulation получает
новый world; старый идентификатор не относится к следующему раунду.

Реестр хранит привязки к физическому телу, положению, визуальному компоненту,
прототипу предмета, контейнеру, доступам, персонажу или двери. Позиции в снимках
читаются из действующих тел Rapier. Через entities() сервер публикует компонентные
снимки, включая идентификаторы. Это типизированный реестр, не универсальный ECS
с планировщиком систем и произвольным добавлением компонентов во время игры.

API: spawn_prototype, despawn_entity, contains_entity, entities.
Удаление снимает предмет из рук и слотов всех персонажей, убирает его из контейнера,
отменяет связанные действия и удаляет тело/коллайдер. Удаление контейнера освобождает
содержимое; удаление двери очищает её воксели. При удалении персонажа вещи остаются
в мире. Локальный системный персонаж 0 удаляется вместе с раундом.

Существующие игровые адаптеры пока сохраняют внутренние индексы предметов. Они не
переиспользуются в пределах раунда: удалённые записи становятся невидимыми пустыми
записями. Лимит — 4096 записей предметов за раунд. Четыре совместимых ключа карты
flashlight/crate/helmet/crowbar сохраняются независимо от порядка JSON-массива;
основной контейнер пока один. Общие ID уже используются рядом с индексами, но это
не заявление о полной миграции всех игровых систем на универсальный ECS.

Протокол Station v7 передаёт ID объектов в снимках и ссылки в командах. Сервер
сопоставляет ссылки с текущими сущностями перед действием. Проверка эпохи раунда
остаётся дополнительным барьером. Одних старых индексов для действия недостаточно.
Клиент и сервер необходимо обновлять вместе.

## Проверки

57 тестов прошли по workspace/пакетам: 35 симуляции, 15 сервера, 4 клиента,
3 рендерера. Сборка --locked, Clippy --all-targets -D warnings и diff --check прошли.

Новые проверки: неверные определения, новый прототип и геометрия без кода,
повторное использование слота реестра, чужой мир, удаление физики и вещей из рук,
отмена работы, содержимое контейнера, дверь, удаление/создание персонажа,
отклонение старой ссылки через mailbox, сохранение выбранного набора контента
и новые ID после перезапуска раунда.

Два отдельных графических клиента подключались к серверу с внешним variant.json.
В JSON добавлены розовый «Сигнальный куб» и новое название двери; клиентам отдельный
файл не передавался. Сценарии профессий и нажатия кнопок дверей прошли, оба процесса
завершились с кодом 0. Файл, логи и PNG сохранены в evidence/entities/.

Новый реестр и формат данных написаны для станции; вся архитектура RobustToolbox
не переносилась. Ранее перенесённые и проверенные rust-anything правила SS14
продолжают использоваться для слотов, действий, доступов и сетевого сглаживания.
