# SS14 → Rust: инвентарь, руки и контекстные действия

Источники зафиксированы, а не взяты из меняющегося main:

- Space Station 14: `space-wizards/space-station-14`, `f5b48b6547a1f9bfd1f1613d879d68064e22f57f`, MIT. Оригинальные файлы в `reference/`, уведомление в `SS14-LICENSE.txt`.
- rust-anything: `erkamyaman/rust-anything`, `b30206b1af11c58706303dfe20a3bd2d819c1e68`, версия 3.3.0, MIT. Применены analyze, bridge, record, build, diff, gate, bench.
- Horizon: существующая MIT-ревизия `59dff1a36bb3a2308f120480e57a2e01c4ba1aae`.

## Что действительно перенесено

`oracle/Rules.cs` — выделенные из SS14 чистые ветви: проверка флагов одежды/размера кармана из CanEquip, выбор действия OnUseSlot, первые два сравнения Verb.CompareTo, индекс SwapHands. Удалены зависимости от ECS; это адаптер для проверки этих ветвей, а не сборка всего оригинального SS14. `../ss14-rules/src/port.rs` содержит их Rust-реализацию и напрямую включён в station-sim. Сгенерированный C#↔Rust FFI нужен только для проверки и не входит в игровой процесс.

`rust-anything` создал мост и записал ответы C#; Rust-реализация написана вручную и проверена этим мостом. 523/523 сравнений совпали, gate прошёл. `domain-inputs.jsonl` добавляет реальные флаги слотов и границы размеров к генерируемым случаям. `DIFF.json` и `GATE.json` — результаты последнего прогона. Это доказательство только для перечисленных ветвей. BENCH-файлы относятся к первоначальным 255 случаям и включают накладные расходы JSON/FFI; ускорение игры из них не следует.

Клиентский интерфейс переписан на egui/wgpu по структуре SS14 ContextMenuElement/ContextMenuPopup: строки действий, категории, недоступные действия с причиной, ограничение высоты и прокрутка. Это новая реализация, не автоматическая конвертация XAML или точная копия оформления Robust UI. Инвентарь: две руки, выбор активной, 16 слотов, два кармана, экипировка/снятие кликом. Для прототипа определены фонарь, ящик и шлем; остальные слоты пока без соответствующих предметов.

Сервер вычисляет список действий и заново проверяет запрос: ID, расстояние 1.6 м, воксели на пути, занятость руки/слота, флаги одежды и размер. Есть осмотр, подбор, отпускание, бросок, смена рук, экипировка/снятие и переключение состояния фонаря. Спрятанные предметы отключены в Rapier и отсутствуют в рендере; активная рука сохраняет прежний пружинный захват. Команды интерфейса передаются отдельной очередью до 32 запросов; более быстрый клиент не перезаписывает уже принятые клики.

## Границы первого инкремента (контейнеры добавлены ниже)

Полные Robust ECS-события/проверки CanEquip, сетевой транспорт, контейнеры внутри ящиков, перетаскивание, применение одного предмета к другому, инструменты, бой, освещение фонаря и полный контент SS14 не перенесены. Ветка InteractUsing распознаётся, но без обработчика пары предметов возвращает отказ, сохраняя оба предмета. Текстовая сортировка CompareTo по CurrentCulture не перенесена. Графические ресурсы SS14 не включены. Шрифт Geist уже присутствовал в Horizon; его SIL OFL сохранена в crates/horizon-theme/fonts/OFL-Geist.txt.

## Повторение

Требуются Rust/Cargo и .NET 10 SDK. Собрать rust-anything на указанной ревизии. Из корня Horizon:

```powershell
./station/ss14-port/verify.ps1 -RustAnything /absolute/path/to/rust-anything.exe
cargo test --manifest-path station/Cargo.toml --workspace --locked
cargo clippy --manifest-path station/Cargo.toml --workspace --all-targets --locked -- -D warnings
cargo run --manifest-path station/Cargo.toml -p station-client --locked -- --smoke --smoke-ui
```

Последний прогон подаёт события мыши в egui: нажимает «Взять в руку», затем «Левый карман». Он проверяет, что сервер поместил тот же предмет в слот, освободил руки и скрыл тело, и сохраняет `station/evidence/wgpu-inventory.png`. Это проверка маршрута egui→очередь→сервер→снимок→рендер; нативная доставка событий ОС этим тестом не проверяется.

## Контейнеры и применение предметов — следующий инкремент

Ящик (ID 1) теперь заперт и имеет два места для небольших предметов. Лом (ID 3)
лежит рядом: взять в активную руку, ПКМ по ящику → «Вскрыть замок инструментом»,
затем «Открыть ящик». В окне содержимого можно положить предмет из руки и взять
выбранный предмет. ЛКМ с предметом в руке применяет его к цели: лом вскрывает
запертый ящик, применение к открытому ящику помещает предмет внутрь.

Сервер повторно проверяет активный предмет, расстояние, воксели на пути,
замок, открытость, размер и свободное место. Take проверяет принадлежность
предмета этому ящику. Недоступное содержимое не передаётся в списке снимка.
Предметы в ящике выключены в Rapier, сохраняют ID и состояние; при извлечении
возвращаются в активную руку. Самовложение и переполнение запрещены.

`station/sim/src/storage.rs` — правила и переходы состояния; клиент получает
StorageSnapshot через существующую серверную границу. Это один контейнер
прототипа, без сетевого транспорта, вложенных контейнеров и сохранений на диск.
В первом инкременте вскрытие было мгновенным (таймер добавлен ниже). Износ инструмента, доступ по ID-картам,
ECS-события и полноценная сетка размещения SS14 не реализованы.

Из той же закреплённой ревизии SS14 взяты чистые проверки
BypassLockSystem.OnInteractUsing и размерные ветви SharedStorageSystem.CanInsert.
Оригиналы добавлены в reference/. Адаптер storage-oracle/Rules.cs исключает ECS;
../ss14-storage-rules/src/port.rs включён в симуляцию напрямую. rust-anything
создал мост: 181/181 сравнений C#↔Rust прошли, STORAGE-GATE.json — PASS.
Вместимость в два места — собственное правило прототипа, не перенос алгоритма
упаковки сетки SS14. Проверка:

```powershell
./station/ss14-port/verify-storage.ps1 -RustAnything /absolute/path/to/rust-anything.exe
cargo run --manifest-path station/Cargo.toml -p station-client --locked -- --smoke --smoke-storage
```

Smoke подаёт события мыши egui, проходит путь до ящика, берёт лом, вскрывает и
открывает ящик, кладёт лом и фонарь, достаёт фонарь, включает и возвращает его,
закрывает и вновь открывает ящик. Проверяет два сохранённых ID, состояние фонаря,
пустые руки и отсутствие сохранённых предметов в мире. Снимок:
station/evidence/wgpu-storage.png. Это проверка UI→сервер→снимок, не нативных
событий мыши ОС. Фонарь сохраняет флаг включения, но физический свет ещё отсутствует.

## Длительные действия

`station/sim/src/actions.rs` реализует серверный автомат: начало → ожидание →
отмена либо однократное применение результата. Это собственная адаптация для
локального прототипа, а не перенос всего Robust DoAfter. Взяты две чистые ветви
проверки рук из SharedDoAfterSystem.ShouldCancel: BreakOnDropItem и
BreakOnHandChange. Условие NeedHand/существование рук считается выполненным;
прочие события, сетевые часы, prediction, задержки урона, состояния мобов и
очереди нескольких игроков сюда не входят.

Исходники той же MIT-ревизии в reference/SharedDoAfterSystem.Update.cs и
reference/DoAfterArgs.cs. C#-адаптер: action-oracle/Rules.cs. rust-anything создал
мост ss14-action-rules, записал и сравнил 154 случая: ACTION-DIFF.json 154/154,
ACTION-GATE.json PASS. В симуляции используется чистый port.rs, без FFI.
Таймер, проверка пола и обновление коллизий проверены собственными Rust-тестами;
эти части не входят в сравнение C#↔Rust.

```powershell
./station/ss14-port/verify-actions.ps1 -RustAnything /absolute/path/to/rust-anything.exe
```
