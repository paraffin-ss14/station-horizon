# Редактор шаблона станции

Запуск из корня репозитория:

```powershell
cargo run --manifest-path station/Cargo.toml -p station-client --locked --offline -- --editor
# Открыть существующий шаблон и сохранить копию:
station/target/debug/station-client.exe --editor --content station/content/station.json --map-output my-station.json
# Играть локально или поднять сервер на отредактированной карте:
station/target/debug/station-client.exe --content my-station.json
station/target/debug/station-server.exe --listen 127.0.0.1:4000 --content my-station.json
```

ЛКМ применяет выбранный инструмент, WASD перемещает камеру. Кнопки палуб переключают уровни 0 и -4. Esc сбрасывает первый угол прямоугольника. Точки появления отмечены зелёным, двери — жёлтым с маской доступа.

- Пол, двухблочная стена, удаление пола, удаление стены/двери.
- Прямоугольная кисть для геометрии: два клика, одна операция истории. Выберите разные X и Y: нулевая ширина/высота по перенесённому правилу SS14 даёт пустое выделение. Одиночный режим ставит одну клетку.
- Дверь: название и требуемые допуски. Пустой набор разрешает доступ всем; инженер + врач требует оба допуска. Повторное размещение обновляет дверь в клетке.
- Предмет: прототип из контента; новый объект или перемещение выбранного ключа. Перемещение сохраняет его прототип. Удаление убирает дополнительные предметы в клетке на выбранной палубе.
- Появление: выберите роль, позднее прибытие или локальную точку, затем клетку. Сохраняется позиция шаблона; существующая логика прибытия может добавить смещение по ID игрока.
- 64 шага отмены/повтора. Новое изменение после отмены сбрасывает повтор.
- Загрузка и закрытие окна запрашивают отказ от несохранённых изменений. Некорректная загрузка сохраняет текущую карту. Сохранение проверяет данные, пишет временный файл и заменяет целевой файл после успешной записи.

Это отдельный локальный режим, без подключения к живому серверу. Сохраняется JSON контента для старта новых раундов, без игроков, таймеров, открытых дверей и текущей физики. Сохранённый файл используется существующим `--content`, в том числе после сброса раунда.

## Границы первого инкремента

Редактирование в пределах ±64 клеток, две палубы, до 4096 клеток за одну операцию; общий предел контента 1 MiB и прежние лимиты объектов. Четыре совместимых ключа `flashlight`, `crate`, `helmet`, `crowbar` нужны текущим игровым адаптерам: перемещать можно, удалять нельзя. Прочие предметы удаляются. При изменении геометрии существующий астероид seed=7 материализуется в обычные воксели; изменённая карта становится статическим шаблоном. Размер персонажа и комплекты профессий сохраняются, но отдельного UI для их редактирования нет.

Редактор проверяет структуру и пределы данных, но не гарантирует проходимость станции: можно поставить стену в точке появления или убрать весь пол. Произвольное число палуб и сетевой совместный редактор не реализованы.

## Перенос через rust-anything

`ss14-editor-rules/src/port.rs` — перенос скалярного расчёта числа клеток оси прямоугольной кисти из `Robust.Client/Placement/PlacementMode.cs`, `GridCoordinates`. Источник зафиксирован на `1afd6929b473dd537b42cb668a961c84a2e2e7c6`. Сам расчёт добавлен коммитом `895cd6e03e01c883c3861b875a9e7643e55dafe6` от 19 января 2023 года, под MIT согласно `ss14-port/ROBUST-LEGAL.md`. Сохранены уведомление и лицензия `ss14-port/ROBUST-LICENSE.txt`.

В C# oracle выделена одна ось, единичный шаг сетки и целочисленная разность центров клеток. Проверяются также значения вне редакторского диапазона; арифметика исходного float сохранена. Старые классы редактора и SnapgridCenter целиком не копировались: в их истории есть код до перехода на MIT. UI, история, файлы и адаптация к вокселям написаны для нашего Rust-прототипа. Это перенос одного правила, а не всего редактора SS14.

Rust-anything 3.3.0: analyze → bridge → record → build → gate. **530/530** записанных случаев совпали, gate passed. Повторить:

```powershell
station/ss14-port/verify-editor.ps1 -RustAnything <полный-путь-к-rust-anything.exe>
```

`EDITOR-BENCH.json`: C# около 84.5 ns, Rust через проверочный JSON/FFI-мост около 2930 ns на вызов (мост медленнее). Это не заявка на ускорение: в игре вызывается Rust-функция напрямую, C# и FFI не используются. Мост служит только для проверки переноса.
